# opencode vs crush

## Quick Reference

| Dimension | opencode | crush |
| --- | --- | --- |
| Primary form factor | Client–server agent for terminal clients | Single-process Bubble Tea assistant |
| Core languages | TypeScript (server, TUI, tooling) | Go (CLI, TUI, backend) |
| Runtime targets | Cloudflare Workers + bun runtime + TypeScript TUI | Local execution with embedded SQLite |
| Default storage | Durable Object + R2 (session sharing) | `.crush` data directory with SQLite DB |
| CLI entrypoint | `packages/opencode/src/index.ts` | `main.go` + `internal/cmd/root.go` |
| Tooling approach | Unified tool registry (`packages/opencode/src/tool/registry.ts`) exposed over HTTP | Go interfaces in `internal/llm/tools` and permission guardrails |
| SDK availability | Generated JS/Go SDKs under `packages/sdk` | No first-party SDK; CLI/TUI only |
| Infra provisioning | SST + Cloudflare definitions in `infra/` | Taskfile + Go toolchain; no cloud dependencies |

---

## Product Intent & Philosophy

- **opencode** positions itself as an open terminal-first coding agent that can be driven locally or remotely. It emphasises provider agnosticism, multi-client support, and a sharable server API (`README.md`, `wiki/02_Architecture_Overview.md`).
- **crush** focuses on being a self-contained “coding bestie” with a rich terminal UI. It prioritises portability across operating systems, strong defaults, and offline friendliness (`README.md`, `wiki/02_Architecture_Overview.md`).

---

## High-Level Architecture

### opencode

- CLI bootstraps a TypeScript service via `yargs`, registering subcommands like `run`, `tui`, `serve`, and `mcp` (`packages/opencode/src/index.ts`).
- The business layer lives in `packages/opencode/src/`, split into agent, session, project, provider, permission, and tool namespaces.
- The TypeScript TUI (`packages/opencode/src/cli/cmd/tui`) is built with OpenTUI/SolidJS and communicates directly with the server layer.
- Cloudflare Worker handler (`packages/function/src/api.ts`) plus Durable Object (`SyncServer`) backs real-time sharing and persistence.

### crush

- Single binary entrypoint in `main.go` wires Cobra commands from `internal/cmd/root.go` and launches the Bubble Tea program (`internal/tui/tui.go`).
- Business services (sessions, messages, permissions, providers) run in-process under `internal/` and communicate via a pub/sub broker (`internal/pubsub`).
- SQLite schema and queries are generated via sqlc (`internal/db/sql`, `internal/db/*.sql.go`), with migrations in `internal/db/migrations/`.

---

## Runtime & Deployment

- **opencode**:
  - Requires bun runtime locally for both server and TUI, but server deployment is optimised for Cloudflare Workers via SST (`sst.config.ts`, `infra/app.ts`).
  - Durable Objects store session metadata, while R2 keeps shared transcripts (`packages/function/src/api.ts`).
  - `turbo.json` orchestrates multi-package tasks, and `bun dev` spins up the service cluster.

- **crush**:
  - Compiles to a single static binary; default environment requires Go 1.25 with `GOEXPERIMENT=greenteagc` (`Taskfile.yaml`).
  - No external infra; data lives under `.crush/` with logs at `.crush/logs/crush.log` (`README.md`).
  - Provides packaged installs for brew, npm, winget, scoop, yay, nix, etc. (`README.md`).

## Data & Persistence

| Aspect | opencode | crush |
| --- | --- | --- |
| Session storage | Cloudflare Durable Object + R2 share bucket (`packages/function/src/api.ts`) | SQLite via `internal/db` with sqlc-generated accessors |
| Config | Minimal `opencode.json` stub; richer settings handled server-side (`packages/opencode/src/config/config.ts`) | Rich JSON config validated against `schema.json`, merged via `internal/config/merge.go` |
| Logs | Optional CLI logging via `Log` util (`packages/opencode/src/util/log.ts`) | Rolling logs with lumberjack in `.crush/logs` (`internal/log/logger.go`) |

---

## Tooling & Extensibility

- **opencode**
  - Tool registry exposes built-ins (file, ripgrep, LSP, bash, webfetch) through a uniform descriptor API (`packages/opencode/src/tool/registry.ts`).
  - Plugin system under `packages/plugin/` and MCP integrations via `packages/opencode/src/mcp`.
  - SDKs generated by Stainless offer JS and Go clients (`packages/sdk/js`, `packages/sdk/go`).

- **crush**
  - Tooling concentrated under `internal/llm/tools/` and `internal/shell/`, guarded by `internal/permission/permission.go`.
  - MCP support across `stdio`, `sse`, `http` defined in config schema (`internal/config/config.go`).
  - Catwalk provider database sync (`internal/llm/provider`, `internal/cmd/update_providers.go`).

---

## Provider & Model Handling

| | opencode | crush |
| --- | --- | --- |
| Provider abstraction | `packages/opencode/src/provider/provider.ts` with lazy init and multi-tenant contexts | `internal/llm/provider` with per-provider structs (Anthropic, OpenAI, Azure, VertexAI, Gemini, Bedrock) |
| Model selection | CLI `models` command; server tracks per-session models (`packages/opencode/src/session`) | Config-driven per-provider defaults (`internal/config/resolve.go`), runtime switching in TUI dialogs |
| Auto updates | Manual config; relies on user-provided credentials | Catwalk sync auto-updates providers unless disabled (`internal/config/config.go`) |

---

## User Interface

- **opencode**
  - TypeScript TUI uses OpenTUI/SolidJS with components under `packages/opencode/src/cli/cmd/tui`, including status, chat, dialog, and prompt modules.
  - Direct integration with server APIs provides real-time streaming updates.
  - Additional web interface at `packages/web/` with SolidStart.

- **crush**
  - Bubble Tea 2 architecture with large component library (`internal/tui/components/*`).
  - Extensive keyboard and dialog management (`internal/tui/keys.go`, `internal/tui/components/dialogs`).
  - Compact, command palette, permissions, and model switcher dialogs covered in wiki guides.

---

## Security & Permissions

- opencode requests confirmation for tool execution server-side via `packages/opencode/src/permission` and shares state with clients through API responses.
- crush embeds permission policies in the config and runtime prompts (`internal/permission/permission.go`), exposing a `--yolo` CLI flag for auto-approvals (`internal/cmd/root.go`).

---

## Developer Workflow

- **opencode**
  - Monorepo controlled with bun workspaces (`package.json`) and Turbo pipeline.
  - `bun dev` for local server, `bun run packages/opencode/src/index.ts` for CLI entry.
  - Stainless-generated SDKs require coordination with core team (`README.md` note).

- **crush**
  - Go modules with `Taskfile.yaml` for lint/build/test/profiling.
  - Uses `golangci-lint`, `gofumpt`, `go test ./...`.
  - sqlc and goose manage database layer (`sqlc.yaml`, `internal/db/migrations`).

---

## Documentation & Knowledge Base

- Both repos ship a `wiki/` folder with matching structure, but contents differ:
  - opencode wiki stresses cloud architecture, tool registry, and remote workflows.
  - crush wiki highlights Bubble Tea UI design, testing strategy, risk management, and architecture mermaid diagrams.

---

## Notable Features Unique to Each

- **opencode**
  - Cloudflare Durable Object-backed live sharing (`packages/function/src/api.ts`).
  - Multi-language SDKs and plugin templates.
  - Server-first design enabling remote control (TUI, web, future clients).

- **crush**
  - Embedded SQLite session history with auto summarisation control (`internal/session`, `internal/config/options`).
  - Catwalk provider registry sync and JSON Schema-driven user config (`schema.json`).
  - Rich Bubble Tea component suite tuned for mouse/keyboard interactions.

## File Layout Snapshot

### opencode (selected directories)

- `packages/opencode/` – CLI + server logic + TUI (TypeScript)
- `packages/function/` – Cloudflare Worker API
- `packages/web/` – SolidStart web app
- `packages/ui/` – Shared UI components
- `packages/sdk/` – TypeScript SDK
- `infra/` – SST infra definitions

### crush (selected directories)

- `internal/cmd/` – Cobra CLI commands
- `internal/tui/` – Bubble Tea pages/components
- `internal/llm/` – Agent, providers, prompts, tools
- `internal/session/`, `internal/message/`, `internal/history/` – Persistence services
- `internal/db/` – sqlc generated DB code and migrations
- `scripts/`, `Taskfile.yaml` – Dev automation

---

## When to Choose Which

- Pick **opencode** if you need a server-accessible agent with pluggable clients, cloud deployment, and SDK integrations.
- Pick **crush** if you want a self-contained terminal experience with minimal dependencies and strong offline support.
